# Чеклист визита на производство — от подготовки до запуска MVP

> **Подготовлено**: 2026-11-17 | **Статус**: рабочий чеклист, отмечать по ходу
> **Связанные документы**: [`interview-guide.md`](interview-guide.md) (вопросы), [`service-blueprint.md`](service-blueprint.md) (карта процесса), [`../../reports/data_request.md`](../../reports/data_request.md) (форматы данных), [`../plans/2026-11-14-pilot-track-a.md`](../plans/2026-11-14-pilot-track-a.md) (план пилота)
> **Правило визита**: уехать с минимальным набором данных (приоритет 1) или с конкретными датами их передачи. Визит без того и другого = потерянный день.

---

## 1. До визита (D-3 … D-1)

- [ ] Письмо владельцу проверено и отправлено ([`../../reports/owner_email_draft.md`](../../reports/owner_email_draft.md)) + приложен запрос данных.
- [ ] Кейс-презентация по сантехнике найдена и приложена к письму (в репозитории её нет — обязательство с встречи 11.11).
- [ ] День визита согласован, владелец подтвердил участие сотрудников (продажи, снабжение, технолог, цех, ОТК).
- [ ] NDA готов к подписанию (локальная обработка, без облака, обезличивание клиентов).
- [ ] Распечатаны: гайд интервью, одностраничник демо, запрос данных. Бумага работает там, где ноутбук — инородный предмет.
- [ ] Ноутбук: локальный контур (никакой облачной синхронизации папки приёма), пустая папка `inputs/owner_data/` для файлов, заряжен + пауэрбанк.
- [ ] Телефон: камера работает, место есть; фото документов — только с разрешения (см. §4).
- [ ] Уточнены СИЗ для обхода цеха (очки, жилет, закрытая обувь) и правила фотосъёмки на территории.
- [ ] Прочитаны спеки MVP: [`../../specs/agents/procurement_pool_spec.md`](../../specs/agents/procurement_pool_spec.md), [`../../specs/agents/order_controller_spec.md`](../../specs/agents/order_controller_spec.md) — чтобы задавать вопросы предметно, но не спорить с практикой завода.

## 2. День визита — повестка

| Время | Блок | Выход блока |
|---|---|---|
| 09:00–09:30 | Владелец: мандат, приоритеты, критерий успеха | Мандат на данные, имя спонсора |
| 09:30–10:15 | Продажи + тендерная система | Выгрузка won/lost или скрин формы + дата |
| 10:15–11:15 | Снабженец | Прайсы, условия доставки, топ позиций, контакты |
| 11:15–12:15 | Технолог (калькуляция, make-or-buy) | Шаблон калькуляции, ставки, коэффициенты |
| 12:15–13:00 | Обед (неформально с технологом / начальником цеха) | Отношения, «неофициальные» боли |
| 13:00–14:30 | Обход цеха с начальником: живой заказ по документам | Таблица SLA заполнена, фото бумажного контура |
| 14:30–15:00 | ОТК / склад | Нормативы приёмки, контроля, отгрузки |
| 15:00–15:30 | Диспетчер / очередь ЧПУ | Узкие места, 3–5 заказов для MVP-2 |
| 15:30–16:00 | Владелец: закрытие договорённостей | Даты передачи данных, канал алертов, следующий созвон |

Повестка гибкая: если снабженец доступен только утром — менять порядок, но не выбрасывать блоки 3–5 из гида.

## 3. Минимум, с которым можно уезжать (приоритет 1)

- [ ] **Выгрузка тендеров** (Excel/CSV) — или скриншот формы выгрузки + имя ответственного + конкретная дата передачи.
- [ ] **3–5 живых заказов** для «бегунка»: состав, срок, текущий этап, ответственный менеджер (записать прямо в таблицу SLA / карточки).
- [ ] **Контакты**: снабженец, диспетчер цеха, технолог, ОТК — ФИО + телефон/Telegram + роль в эскалации.
- [ ] **Таблица SLA** ([`interview-guide.md`](interview-guide.md) §3): реальные нормативы переходов, рабочий календарь смен, кто фиксирует факт, как узнают о просрочке.
- [ ] **Прайсы поставщиков** (фото допустимо) + условия доставки: минимальная партия, стоимость рейса.
- [ ] **Канал алертов MVP-2 подтверждён**: Telegram или почта — чем реально пользуются ответственные.
- [ ] **Критерий успеха пилота** словами владельца (цифра в рублях / условие «ни один заказ не забыт»).

Если что-то из приоритета 1 не получено — на закрытии зафиксировать: кто, что, к какой дате. Без даты пункт считается проваленным и эскалируется владельцу при следующем созвоне.

## 4. Протокол фото и сканирования

Снимать **с разрешения**, людей не фотографировать:

- [ ] Бумажный маршрут живого заказа (все листы: задание, накладные, замеры) — обезличить клиента при оцифровке.
- [ ] Журнал приёма заказов / доска планирования цеха.
- [ ] Прайсы поставщиков, условия доставки (у снабженца).
- [ ] Шаблон калькуляции себестоимости (у технолога).
- [ ] Форма выгрузки тендерной системы (скриншот экрана).
- [ ] Журнал брака / входного контроля (если ведут).
- [ ] Шильдики станков и стойки ЧПУ — **опционально**, для фазы 2 (телеметрия); не тратить на это время, если приоритет 1 не закрыт.

Каждое фото сразу подписывать в заметках: что, у кого, дата. Вечером без подписей половина снимков станет бесполезной.

## 5. Конфиденциальность (обязательства из письма)

- Все файлы и фото — только в локальную папку `inputs/owner_data/`, **без облака** (iCloud/Drive/Dropbox синхронизацию этой папки отключить).
- Имена клиентов, контакты, договорные цены — обезличивать при переносе в vault и отчёты (замена на «Клиент А», «Заказ №»).
- NDA подписан или озвучена готовность подписать; не передавать данные третьим лицам и не использовать для других клиентов.
- Обработка чувствительных данных — локальный LLM-контур (раздел ещё не специфицирован, техдолг §6 плана; до его закрытия реальные данные не прогонять через облачные модели).

## 6. Сигналы go / no-go и запасные ходы

| Сигнал | Что делать |
|---|---|
| Владелец даёт мандат, сотрудники открыты | ✅ Go: старт MVP-1 по получении выгрузки |
| Выгрузку «не могут сделать» | Попросить скрин формы + 20–30 строк вручную за последний месяц; этого хватит для первой ретроспективы |
| Снабженец закрыт, цены не даёт | Работать через владельца и обезличенные прайсы; MVP-1 начать с тендерной ретроспективы (она не требует прайсов) |
| Цех сопротивляется («слежка») | Подчеркнуть: статусы вводит офис, цех не трогаем; показать выгоду начальнику цеха (меньше беготни, его слова из интервью §2.5) |
| Данных нет вообще через неделю после визита | Созвон с владельцем: минимальный набор п.1–3 или перенос сроков пилота; не строить дальше на гипотезах |

## 7. В тот же вечер (D+0)

- [ ] Таблица SLA перенесена в спеку/конфиг (канонические нормативы вместо гипотез).
- [ ] 3–5 заказов заведены в vault по [`../../06_Шаблоны/Шаблон_Заказа.md`](../../06_Шаблоны/Шаблон_Заказа.md) (обезличенно), статусы и timestamps — с сегодняшнего дня.
- [ ] Фото и файлы разложены в `inputs/owner_data/` с описью (что, от кого, дата, чувствительность).
- [ ] Письмо-резюме владельцу: благодарности, договорённости (кто/что/когда), выбранные заказы, дата следующего созвона. Отправить в течение 24 часов.
- [ ] Обновлён DASHBOARD: статус визита и данных.
- [ ] Решение: данных достаточно для старта MVP-1? Если да — нормализация выгрузки и ретроспектива проигранных тендеров (план §3).

## 8. После визита (D+1 … D+14)

- [ ] MVP-1: нормализация марок стали → ретроспектива проигранных тендеров (дельта «материал / логистика / маржа») → пулы → отчёт с суммами экономии.
- [ ] MVP-2 (со 2-й недели MVP-1): гармонизация контракта статусов (техдолг §6), Dataview-пульт SLA, алерты в подтверждённый канал, журнал потерь.
- [ ] Дизайн-трек: service blueprint верифицирован фактами визита → концепт пульта диспетчера.
- [ ] Отчёт MVP-1 владельцу → разговор о коммерческих условиях (фикс / success fee / гибрид — план §7).
