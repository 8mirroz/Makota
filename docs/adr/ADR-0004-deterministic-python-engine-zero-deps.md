# ADR-0004: Детерминированное модульное Python-ядро без внешних зависимостей и слой Obsidian Vault

## Status

Accepted (2026-11-18)

## Context

Промышленные предприятия предъявляют жёсткие требования к стабильности, аудируемости и автономности программного обеспечения:
1. В закрытых заводских сетях (Air-Gapped LAN) установка внешних Python-пакетов из PyPI часто заблокирована политиками ИБ.
2. Использование генеративных языковых моделей (LLM) для калькуляции себестоимости, расчёта точки безразличия Make-or-Buy или составления расписания ЧПУ недопустимо из-за вероятностной природы вывода и риска арифметических галлюцинаций.
3. Монолитное смешение парсинга Markdown-карточек, доменных расчётов и генерации отчётов в одном скрипте затрудняет модульное тестирование и расширение системы.

## Decision

1. **Zero-Dependency Standard Library Engine**: Всё вычислительное ядро `engine/` реализуется исключительно на стандартной библиотеке Python 3.8+ (`dataclasses`, `datetime`, `pathlib`, `json`, `re`, `argparse`).
2. **Строгая модульная декомпозиция `engine/`**:
   - `engine/cost_calculator.py` — 3-маршрутное моделирование себестоимости по ISO 23247, анализ тендерных ставок и расчёт точки безразличия Make-or-Buy ($N^*$).
   - `engine/order_sla_tracker.py` — контроль нормативов времени переходов между отделами («Цифровой бегунок»).
   - `engine/procurement_matcher.py` — агрегация потребностей в металле в оптовые пулы с учётом временных окон консолидации (`max_date_delta_days`).
   - `engine/logistics_validator.py` — проверка транспортных ставок по рыночным коридорам АТИ.СУ.
   - `engine/production_planner.py` — детерминированное расписание станков ЧПУ по правилу EDD (Earliest Due Date) с матрицей переналадок `specs/agents/planner_setup_matrix.json`.
   - `engine/vault_parser.py` — изолированный парсер и валидатор YAML frontmatter карточек Obsidian Vault.
   - `engine/vault_runner.py` — CLI-оркестратор сводного пилотного отчёта `reports/pilot_report.md` (с сохранением обратной совместимости реэкспорта функций парсера).

## Consequences

- **Позитивные**: Мгновенное выполнение всего тестового люкса (43 теста за ~0.15 сек); 100% воспроизводимость расчётов на любой ОС без настройки виртуальных окружений; чистое разделение слоёв парсинга, бизнес-логики и представления.
- **Ограничения**: Парсер `parse_frontmatter` поддерживает плоский одноуровневый YAML frontmatter (достаточный для всех карточек Obsidian Vault).

## Rollback

Каждый модуль `engine/` изолирован и покрыт независимыми unit-тестами; откат любого компонента выполняется атомарно через Git.

## Validation

- Полный прогон тестов: `python3 -m unittest discover -s tests -v` (43 теста, 0 внешних зависимостей).
