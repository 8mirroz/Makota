## Ограничения и переходные состояния

- **Приоритет меток времени этапа (`stage_entered_at`)**: Для детерминированного расчёта времени нахождения на текущем этапе парсер `engine/vault_parser.py` читает поля frontmatter в строгом порядке: `stage_entered_at` $\to$ `updated_at` $\to$ `created_at`. Это предотвращает ложные срабатывания SLA от даты первичного создания заказа.
- **Терминальные состояния (`TERMINAL_STAGES`)**: Статусы `09_закрыт_прибыль_зафиксирована`, `11_закрыт_прибыль_зафиксирована`, `99_отменен` и `99_отменен_проигран` являются завершёнными и никогда не генерируют SLA-алертов (`is_breached = False`, `risk_level = "OK"`).
- Статус `05_ожидание_сырья` в Vault покрывает два SLA-этапа: `03_metal_procurement` и `04_warehouse_inbound`. Для точного SLA-контроля рекомендуется использовать промежуточную карточку снабжения в `04_Снабжение_и_Кооперация/`.
- Статус `07_в_очереди_цеха` из JSON Schema отсутствует в Vault — это внутренний буфер Production Planner, не требующий ручного обновления.
- Статус `09_закрыт_прибыль_зафиксирована` добавлен в шаблон заказа для замыкания P&L контура.
